# AlphaNode: диверсность как цель поиска + авторесёрч

*Черновик предложения, 2026-08-22. Цифры — с прод-ноды 1h (6 пар, 276 раундов).*

## 1. Проблема

Поиск сошёлся в одну идею и полирует её.

| факт | значение |
|---|---|
| формул в `library_1h.jsonl` | 3 736 (1.17 млн проб) |
| из них с геном `ts_min:10(sign(ret))` | 941 |
| семей по корреляции `capital_ret` (TRAIN+VAL, ρ ≥ 0.6) | 129, но одна семья — 596 формул и весь топ-300 |
| портфель top-6 по fitness | попарная ρ > 0.6, eff_n ≈ 1.5, все long-only |
| TEST-Sharpe портфеля | **0.36** — ниже любого из его членов (0.34–0.88) |
| комбинации лидеров семей (отбор по TRAIN+VAL) | TEST **−0.3…−1.3** |

Почему так:

- `corr_penalty` мягкий — штраф за похожесть не мешает клонам занимать зал славы;
- дедуп в `_pick_top` текстовый (`SequenceMatcher ≥ 0.85`) — замена `mul → add` или `high → vwap` делает формулу «другой» при том же поведении;
- `seed_from_lib = true` — каждый раунд стартует с тех же чемпионов и возвращается в ту же яму;
- fitness `min(train, val)` ≈ 3.0 при TEST 0.4 — отбор переобучается на VAL.

## 2. Доработка: niche-based Hall of Fame

Пишется руками один раз. Место в зале славы ограничено **на идею**, а не на формулу.

1. **Похожесть — по поведению, не по тексту.** Для кандидата считаем корреляцию `capital_ret` (fastsim, ~1 с/формула) с лидером каждой семьи на окне отбора.
2. **Семьи.** `|ρ| ≥ θ` с каким-то лидером → кандидат попадает в эту семью и конкурирует только с родственниками. `|ρ| < θ` со всеми → новая семья, ей гарантировано место.
3. **Квота** `k` мест на семью. Вытеснить можно только родственника; освободившиеся места достаются другим семьям, даже с меньшим fitness.
4. **Seed** нового раунда — по одному лидеру от семьи, а не глобальный топ-N.
5. Дополнительно — чистка «мусорных генов»: поддерево, константное на ≥ 90 % баров (`tanh(open)`, `cs_scale(sign(high))`), вырезается — оно создаёт ложную «разность» и раздувает формулы.

**Метрика успеха** (одна, считается `library_rescore`):

- число семей с `base > 1.5` и `max|ρ| < 0.5`;
- TEST-Sharpe портфеля из лидеров этих семей — TEST в отбор не входит, поэтому число честное.

## 3. При чём тут авторесёрч

У механизма четыре ручки без известных правильных значений, и у каждой — противоположные побочки:

| ручка | диапазон | мало | много |
|---|---|---|---|
| порог θ | 0.4 / 0.5 / 0.6 / 0.7 | сотни шумовых семей по одной формуле | снова монокультура |
| квота k | 1 / 2 / 3 / 5 | идея не дошлифовывается | клоны |
| окно для ρ | TRAIN / TRAIN+VAL / последний год | — | — |
| seed от семей | on / off | — | — |

≈ 100 конфигов × 5–10 часов ноды каждый. Вручную не делается — человек сдаётся после третьего прогона.

**Авторесёрч** — цикл, который это делает сам:

```
конфиг → нода в отдельный ALPHANODE_STATE_DIR с фиксированным бюджетом раундов
       → library_rescore → метрика из §2 → журнал гипотез → следующий конфиг
```

Планировщик — grid / bayes или LLM-агент, читающий журнал. Инфраструктура в проекте уже есть: CLI, изолированные state-каталоги, `library_rescore.py`, `experiments.py`.

**Разделение труда:** человек задаёт *что* менять, автоматика отвечает *какие значения* работают и не ломают друг друга.

## 4. Что ещё отдать тому же циклу (после семей)

1. **Честный fitness** — блочный (`fit_blocks`, уже в коде, выключен) / walk-forward / штраф за разрыв TRAIN−VAL. Метрика: корреляция fitness ↔ TEST-Sharpe по библиотеке (сейчас ≈ 0).
2. **Вселенная и таймфрейм** — 6 / 20 / 50 пар, 1h / 4h / 1d. На 6 парах cs-операторы бесполезны и все альфы long-only; на 30+ должны появиться long/short.
3. **Комбинатор портфеля** — корреляционный дедуп вместо текстового, риск-паритет между членами (сейчас Σ w×leverage — доминирует самый плечевой), отбор по вкладу в Sharpe портфеля.
4. **Исполнение** — проскальзывание и funding в PnL fastsim; на 1h при fee 0.1 % это может съесть Sharpe 0.4 целиком.

## 5. Финальный судья

Всё выше только ранжирует кандидатов. В прод — по **forward track**: минимальный срок на живых барах, минимальный Sharpe, просадка относительно корзины. Это замыкает цикл и убирает cherry-pick по TEST.

## Одной фразой

Поиск работает, но сходится в одну идею. Авторесёрч нужен не чтобы искать быстрее, а чтобы автоматически подбирать *условия* поиска — диверсность, честный fitness, вселенную — и проверять каждый вариант по одной метрике на held-out и форварде.
