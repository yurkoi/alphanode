GUI guide

The desktop app is a settings sidebar on the left and a live dashboard on the right. The split, the chart height and the portfolio panel height are all draggable — grab the gaps between blocks; double-click a handle to reset.

Search settings (sidebar)

  • Timeframe — the bar size for the whole pipeline. Picking one fills in the recommended date segments and pair count. Each timeframe keeps its own data snapshot, library and history — they never mix.
  • Universe — all downloaded pairs, or an explicit comma-separated list.
  • Segments — TRAIN / VAL / TEST boundaries. TEST is the held-out window: the search never selects by it.
  • Simulation — target volatility and execution cost (fees+slippage per side).
  • GA parameters — population, generations per round, tournament size, elitism, random injection, crossover probability, parsimony (complexity penalty), correlation threshold/penalty, Hall-of-Fame capacity.

Dashboard

Status + progress chart

Round and generation counters, evaluation speed, a live activity log, and the best-fitness curve of the current round.

Leaderboard

The alpha library ranked by your chosen column. Colums include size, fitness (min TRAIN/VAL Sharpe), and Sharpe / MaxDD / CAGR / bars per segment. The row context menu and toolbar let you:

  • copy a formula, or plot its full equity curve;
  • export the library to CSV;
  • generate a PDF analytics report;
  • serve the alpha as a live signal API (daily).

Portfolio

Combines the library's top-N into one book and shows combined TEST metrics vs an equal-weight buy-&-hold basket, plus the equity chart. Two selection modes:

ModePicks byMeaning of the combined TEST numbers
TESTheld-out TEST Sharpe Optimistic (the same window picked the members — a cherry-pick). Treat as a shortlist; validate forward.
fitnessmin(TRAIN, VAL) Sharpe Honest out-of-sample: TEST never entered selection.

On daily bars the combination runs through the real portfolio engine (identical to the paper/serve products); intraday it runs through the search engine with the same combiner semantics — the label under the metrics always tells you which.

Data & processes

Download data fetches/refreshes the per-timeframe snapshot. The node, signal services, portfolio builds and PDF reports run as separate background processes — the GUI stays responsive, survives restarts, and re-adopts running services on launch.

All state lives in one folder (settings, per-timeframe libraries, search history, portfolio docs). "Wipe history" in the settings clears search artifacts but never touches your data snapshots.
